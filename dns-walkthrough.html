How a website address finds this site

A plain-language DNS walkthrough by Muhammad Haroon Khan.

What DNS does

DNS is the internet's address directory. People remember names such as example.com, while computers need an address or hosting destination. DNS connects the readable name to the technical place that can answer the request. It does not store the website itself; it tells the browser where to look for it.

What a CNAME record means

A CNAME record makes one hostname an alias of another hostname. For example, I could point www.myname.com to haroonk2607.github.io. The DNS response would tell the resolver to continue with the GitHub hostname, and GitHub Pages would serve the site. A CNAME points to a name, not directly to a numeric IP address. That lets the hosting provider change its infrastructure without requiring me to update an IP every time.

What happens after someone types the address

  1. The browser checks whether it already knows the answer from a recent cached visit.
  2. If not, it asks a DNS resolver, usually operated by the network provider or a public DNS service.
  3. The resolver follows the DNS hierarchy until it reaches the authoritative nameserver for the domain.
  4. The authoritative nameserver returns the relevant record. This could be an A or AAAA address record, or a CNAME alias that leads to the host.
  5. The resolver returns the final destination to the browser and keeps it for the record's allowed cache time.
  6. The browser opens an HTTPS connection to the host. The host checks the requested hostname, chooses the correct site, and returns its HTML, CSS, fonts, and images.
  7. The browser verifies the HTTPS certificate, then renders the files as the page on screen.

In short: the resolver finds the authoritative nameserver, the DNS record identifies the destination, and the hosting service sends back the website. DNS answers "where?"; the host answers with "here is the site."
