Plain-words explainer

How the refresh review score works

This feature makes one transparent prioritisation rule interactive. It runs on GitHub Pages for free and keeps every value inside the visitor's browser.

What a backend is

A backend is code running on a server instead of in the visitor's browser. It can receive requests, save data, use private credentials, query a database, or run a model. This demo does not need one because it saves nothing and uses a small public formula. GitHub Pages only sends the HTML, CSS, and JavaScript files to the browser.

What the feature does

The visitor enters impressions, CTR, and average position. The rule compares CTR with a published position-tier reference and gives more weight to pages with more impressions. The output is a score from 0 to 100 and one review action: monitor, add to the queue, or review the snippet now.

How the data flows

  1. The browser loads the static site files from GitHub Pages.
  2. The visitor types three values into the form.
  3. JavaScript validates the values and runs the rule locally.
  4. The page updates the score, action, reason, and progress meter.
  5. No form request is sent, and no input is stored or emailed.

What it does not claim

The score is a review aid, not a trained production model and not a promise that editing a page will recover traffic. A reviewer still needs query intent, SERP context, and editorial judgment before acting.
